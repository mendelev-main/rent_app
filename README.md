# Rent App

Telegram Mini App + Telegram Bot для бронирования краткосрочного жилья.

## Цель MVP

Создать работающий сервис, в котором пользователь входит через Telegram и может:

- выбрать сценарий «Снять» или «Сдать»;
- как собственник — создать и опубликовать объект жилья;
- как гость — просматривать доступные объекты;
- выбирать даты в календаре;
- отправлять заявку на бронирование;
- получать уведомления через Telegram Bot;
- связываться с другой стороной через Telegram;
- в дальнейшем подключать внешние iCal-календари (Avito / Kufar и другие источники).

## Принципы проекта

1. Telegram — основной канал идентификации пользователя и уведомлений.
2. Данные Telegram Mini App (`initData`) считаются доверенными только после серверной проверки подписи.
3. Backend является источником истины для объектов, доступности и бронирований.
4. Двойное бронирование должно предотвращаться на уровне backend/database, а не только интерфейса.
5. Интеграции Avito/Kufar не должны определять доменную модель. Они подключаются отдельными адаптерами синхронизации.
6. Разработка ведётся небольшими вертикальными итерациями, каждая из которых должна оставлять приложение в рабочем состоянии.

## Планируемый стек

- TypeScript
- React + Vite — Telegram Mini App
- Node.js + Fastify — API / Bot webhook
- PostgreSQL — данные приложения
- S3-compatible Storage / Supabase Storage — фотографии объектов
- Telegram Bot API
- Railway — build/deploy приложения из GitHub

## CI/CD

Production-ветка: `main`.

Railway подключается к этому GitHub-репозиторию. После успешной проверки и push/merge в `main` Railway автоматически собирает и публикует новую версию приложения.

Секреты (`TELEGRAM_BOT_TOKEN`, строки подключения к БД и т.п.) никогда не хранятся в Git и задаются через Railway Variables.

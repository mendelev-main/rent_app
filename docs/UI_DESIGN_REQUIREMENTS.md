# UI / UX Design Requirements

Статус: обязательные требования проекта Rent App.

## 1. Единый стиль

Все экраны Telegram Mini App должны восприниматься как части одного приложения. Новые функции не должны добавляться как визуально изолированные технические формы.

Обязательны единые принципы для типографики, отступов, радиусов, карточек, полей ввода, кнопок, статусов, модальных/служебных сообщений и навигации назад.

Интерфейс должен учитывать Telegram theme variables и одинаково сохранять визуальную иерархию в светлой и тёмной теме.

## 2. Понятность

Пользователь должен понимать основное действие экрана без инструкции. На одном экране должно быть одно очевидное основное действие; вторичные действия визуально слабее.

Названия кнопок описывают результат действия: «Сохранить изменения», «Добавить фотографию», «Опубликовать», а не технические операции.

Статусы (`Черновик`, `Опубликовано`, ошибки, загрузка, успешное сохранение) показываются понятным человеческим языком.

## 3. Mobile-first / Telegram Mini App

Основной сценарий проектируется для телефона внутри Telegram. Интерактивные элементы должны иметь удобную область нажатия, формы — корректные типы клавиатуры, контент — не выходить за viewport и safe-area.

Не использовать мелкие ссылки для основных действий. Не размещать критичные действия слишком близко друг к другу.

## 4. Формы

Поля имеют постоянный стиль label → control → validation/error. Обязательность и ошибки должны быть понятны до или сразу после попытки сохранения.

Введённые пользователем данные не должны исчезать при обычной ошибке сети/API. Во время запроса основная кнопка должна показывать состояние выполнения и защищаться от случайного повторного нажатия там, где повтор опасен.

## 5. Фотографии

Фотографии объекта отображаются как визуальная галерея. Должны быть понятны обложка, удаление и порядок. Основная фотография должна явно отмечаться как «Обложка».

Удаление требует защиты от случайного нажатия. После загрузки/удаления интерфейс сразу показывает актуальное состояние.

## 6. Публикация

«Опубликовать» — отдельное осознанное действие, визуально отличимое от обычного сохранения черновика. Перед публикацией UI и backend проверяют обязательные данные и наличие фотографии. Backend остаётся окончательным источником проверки.

Если публикация невозможна, пользователь получает конкретный список того, что нужно заполнить, а не общую ошибку.

## 7. Состояния интерфейса

Каждый экран/компонент, работающий с backend, должен иметь предусмотренные состояния: loading, empty, success, validation error, network/server error. Не допускаются «мёртвые» кнопки без обратной связи.

## 8. Design Review — обязательная проверка

Каждая новая UI-функция перед отметкой как завершённая проверяется минимум по следующим пунктам:

1. Понятно ли назначение экрана и главное действие без объяснения.
2. Совпадает ли стиль с существующими экранами Rent App.
3. Нет ли визуально конкурирующих основных кнопок.
4. Удобны ли размеры элементов на телефоне.
5. Корректны ли loading / empty / error / success состояния.
6. Не теряются ли введённые данные при ошибке.
7. Понятны ли тексты кнопок, статусов и ошибок обычному пользователю.
8. Корректно ли выглядит интерфейс с Telegram theme variables.
9. Нет ли опасного действия без защиты от случайного нажатия.
10. UI не считается единственной защитой бизнес-правил: критичные проверки повторяются backend.

Функция не должна отмечаться `[x]` в MVP_SPEC как завершённая, если её основной UI-сценарий не прошёл эту проверку.

## 9. Направление дизайна

Визуальное направление: современный, спокойный, чистый интерфейс сервиса бронирования жилья; крупные фотографии, ясная иерархия, минимум визуального шума. Приоритет — понятность и скорость сценария, затем декоративность.
